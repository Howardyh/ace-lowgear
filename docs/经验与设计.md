# 从实测经验到统一设计

## 已经确认的经验

1. IFEO 中的设置正确，不等于运行进程一直保持该优先级。真实 ACE 进程曾在新 PID 下仍显示 CPU Normal，I/O 则保持 Very Low。
2. 管理员读取能成功的进程，在普通检查窗口中可能返回 Win32 5。权限不足是“未知”，不是最低优先级，也不是已经证明进程保护无法读取。
3. CPU 配置枚举和运行枚举不同；未读取的 `0`、`-1` 容易误导，应使用空值和原因。
4. 已实测后台纠正能将新实例和再次变高的实例降为 Idle，用户也提供了两个真实 ACE 实例均达到 CPU / I/O 目标的读值。
5. 单个“最后 CPU”指逻辑处理器，不一定是物理核心。编号从零开始，必须检测活动掩码并正确处理第 63 位。多处理器组需要明确边界。
6. 进程启动、运行一段时间、重新启动与电脑重启是不同的验证层级。临时程序测试不能替代真实 ACE 和游戏的接受测试。
7. 恢复要回到第一次修改前，而不是新版本安装前的已经优化状态；不能让恢复后的后台马上重新写回目标值。
8. 原始值的存在性、类型及内容都要保留，包括空数组、REG_NONE、QWORD 和不展开的环境变量字符串。写入前持久化恢复记录，检测后续修改，失败逐项回滚。
9. 源码应可移动，受信任的执行程序与本机恢复数据应放在管理员可写目录；运行资料不能进入公共仓库。
10. 多个脚本入口、两个版本号和外加管理器提高了理解与维护成本。新版本应统一生命周期、数据结构、权限和结果展示。
11. 用户明确要求每次 ACE 启动后自动执行一次、完成即退出。旧版持续纠错的验证经验用于启动阶段的有限核验，不能据此保留常驻程序。

## 全新架构

| 层 | 文件 | 责任 |
|---|---|---|
| 统一入口 | `LowGear.ps1` | 命令、UAC、64 位与 STA 宿主、结果与退出码 |
| 界面 | `ui/Panel.xaml`、`ui/Panel.ps1` | 中文仪表板，耗时操作放在子进程，界面持续响应 |
| 控制器 | `src/Controller.ps1` | 安装、迁移、暂停、恢复、一次性操作与状态 |
| 状态 | `src/State.ps1` | 原值备份、类型保留、安装归属、完整性和原子写入 |
| Windows 适配 | `src/Platform.ps1` | WMI 启动事件、一次性任务、本地编译、启动自检 |
| 原生运行时 | `src/Runtime.cs` | CPU / I/O 查询及降低、相关性、固定目标、限时核验并退出 |

所有功能从同一个控制器调用同一份运行时，不再叠加第二套补设脚本。安装时本地编译 .NET 执行程序，仅包含本项目源码。Windows 接收匹配程序名的进程启动事件，再通过系统 schtasks 唤起 SYSTEM 一次性任务。没有本项目的常驻轮询进程。

任务先等待约 5 秒，随后在本次启动会话中约每 3 秒设置和回读；两个核心进程均运行、所有运行目标连续三次符合策略后退出。没有目标时退出，未完成时最多约 45 秒并记录结果。计划任务另有 2 分钟上限，单实例、不定期重试、不使用开机或登录触发，不依赖网络或接入电源。

多个管理窗口通过本机共同操作锁串行修改；UI 与任务共享策略文件。默认相关性不变，可明确选择每次启动时绑定。`last-run.json` 原子覆盖最近会话的结果，不无限堆积日志。暂停移除事件订阅并停止任务；完整恢复还移除任务并恢复最早原值。

## 边界与权衡

I/O 的 Native API 信息类属于 Windows 内部接口，可能改变。安装先做当前系统的独立启动自检；运行查询失败时明确报告。降低操作只在读到实际值后执行，拒绝把未知值当成可修改的正常值。没有驱动、注入、保护绕过或全局调度设置。

一次性方案在会话完成后不会再纠正优先级变化，这是按用户要求作出的明确取舍。启动等待与有限核验能覆盖已观察到的启动阶段重设，但不能保证更晚发生的变化，也不能承诺所有线程、驱动和请求的每个瞬间都处于最低级别；不承诺游戏帧数提升。

## 1.2 界面层

界面使用概览、设置、诊断三个保留实例的页面，共享一个只读查询执行线程。导航不增加查询，进程分组更新时保留展开状态，相关性草稿不被周期刷新覆盖。实际修改仍调用既有命令与控制器；仅主题偏好由界面独立管理。

原生 DWM 包装仅对面板 HWND 设置背景、标题栏颜色与圆角，并监听窗口生命期内的系统设置消息。材质不支持或调用失败时恢复实色；关闭后移除监听，在后台完成只读查询资源释放。它不参与 ACE 调度、启动订阅或一次性执行组件。

关闭时只对已经开始的修改操作暂缓退出；尚在等待只读查询的排队操作会取消。系统关闭动画时仅显示中文阶段，不展示持续动画或推测百分比。

## 1.3 外观与位置记忆

`ui/Appearance.ps1` 负责独立偏好文件、字段校验与窗口边界应用；`ui/WindowPlacement.cs` 负责工作区枚举、逻辑尺寸换算与纯几何恢复。旧 `ui.json` 保持仅主题格式，新增的 `appearance.json` 不接触 ProgramData 运行策略。源码版本统一来自公开清单，执行组件仍通过原有 Upgrade 流程切换。

位置使用普通窗口的逻辑尺寸和工作区内相对坐标，附带工作区矩形用于在当前显示器中匹配；不持久化 HWND 或显示器标识。使用当前 WPF CompositionTarget 的比例换算 Win32 屏幕坐标，保留现有宿主的 DPI 感知方式，不声称新增逐显示器 V2 支持。副屏负坐标有效，已移除工作区无重叠时回主屏；工作区不足时优先保证窗口可操作。

启动恢复先适配正常边界，再还原最大化；最小化不作为保存状态。正常关闭时捕获位置，实际 Closed 才写入；修改操作阻止关闭时不覆盖记忆。显示器、工作区或 DPI 消息只设置待检查标记，由现有界面计时器检查可操作标题栏；窗口关闭后移除原生消息钩子，没有新增后台线程或持续显示器查询。静态渲染关闭几何读写，测试句柄必须显式提供隔离偏好路径才启用记忆。
